# Career Guidance AI

面向高校就业办的 AI 升学与就业规划官网 + 演示产品。项目从零开始实现，只保留一个核心选题：用 DeepSeek API 帮助高校展示面向学生的升学、就业、转专业与求职路径规划能力。

这份 README 是给 Harness、Claude Code、Codex 等编码代理执行的产品与实现规格，不是普通宣传文案。实现时请严格按本文边界推进，避免自行扩展成完整平台。

## 产品定位

本项目服务对象是高校就业指导中心、招生就业处、学院辅导员团队与职业发展中心。产品要让这些校内角色快速看到：AI 可以把学生的专业背景、能力基础、目标方向与现实约束转化为一份结构化、可落地的规划建议。

V1 不是学生长期使用的个人系统，而是一个可信、清晰、可演示的官网和 AI 体验入口。官网负责说明价值，演示工作台负责让访客输入一个学生画像并得到一份规划结果。

核心价值：

- 帮高校就业办展示 AI 生涯规划服务能力。
- 帮学生理解升学、就业、转专业、实习与求职之间的路径选择。
- 把模糊目标转化为阶段目标、行动清单、风险提醒和下一步建议。
- 用一个轻量演示验证产品方向，暂不建设账号、数据和后台系统。

## V1 范围

必须实现：

- 官网首页：面向高校就业办，解释产品价值、适用场景、演示流程和交付结果。
- AI 演示工作台：访客填写学生画像、发展目标和现实约束，调用 DeepSeek 生成规划建议。
- 服务端 AI 接口：通过 Next.js API Route 调用 DeepSeek，前端不能暴露 API key。
- 结果展示：以清晰分区呈现规划摘要、路径建议、行动清单和风险提醒。

明确不做：

- 不做登录、注册、权限系统。
- 不做数据库、长期历史记录、用户档案沉淀。
- 不做文件上传、简历解析、批量导入。
- 不做高校后台管理、学生管理、统计看板。
- 不做在线支付、套餐、商业化后台。
- 不做旧项目迁移，不复用旧实现、旧页面或旧设计。

## 技术要求

未来实现请使用：

- Next.js App Router。
- TypeScript。
- 服务端 API Route 调用 DeepSeek。
- 前端只通过本项目的 `/api/plan` 请求 AI 结果。
- 环境变量读取 API key 和模型配置。

推荐路由：

- `/`：官网展示页。
- `/demo`：AI 演示工作台。
- `/api/plan`：DeepSeek 规划生成接口。

页面风格应偏高校服务与专业咨询场景：清晰、可信、克制、信息密度适中。不要做夸张营销页，也不要做复杂 SaaS 后台。第一屏要让人立刻知道这是“高校就业办可用于演示的 AI 升学与就业规划产品”。

## DeepSeek 配置

必须通过环境变量接入 DeepSeek，不允许在代码中写入真实 API key。

```bash
DEEPSEEK_API_KEY=your_deepseek_api_key
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_PRO_MODEL=deepseek-v4-pro
```

默认配置：

- `baseURL`：`https://api.deepseek.com`
- 默认模型：`deepseek-v4-flash`
- 复杂规划可选模型：`deepseek-v4-pro`

实现策略：

- 普通演示请求默认使用 `DEEPSEEK_MODEL`。
- 当输入目标复杂、约束较多或用户选择“深度规划”时，可使用 `DEEPSEEK_PRO_MODEL`。
- 如果 `DEEPSEEK_API_KEY` 缺失，接口应返回清晰错误信息，前端显示可理解的配置提示。
- 前端不得直接请求 DeepSeek，不得把 API key 输出到浏览器、日志或错误详情中。

## AI 演示接口

建议接口：

```http
POST /api/plan
Content-Type: application/json
```

请求输入应包含：

```json
{
  "studentProfile": {
    "grade": "大三",
    "major": "计算机科学与技术",
    "schoolType": "地方本科",
    "skills": ["Python", "数据分析", "项目实践"],
    "interests": ["人工智能", "产品经理", "教育科技"]
  },
  "goal": {
    "type": "就业",
    "target": "互联网产品经理或 AI 应用方向",
    "timeframe": "12个月"
  },
  "constraints": {
    "location": "优先长三角",
    "budget": "有限",
    "weaknesses": ["实习经历不足", "表达能力一般"]
  },
  "mode": "standard"
}
```

返回结果应包含：

```json
{
  "summary": "一句话概括当前最适合的路径",
  "paths": [
    {
      "name": "主路径名称",
      "reason": "为什么适合",
      "steps": ["阶段步骤1", "阶段步骤2", "阶段步骤3"]
    }
  ],
  "actionPlan": [
    {
      "period": "未来30天",
      "tasks": ["具体任务1", "具体任务2"]
    }
  ],
  "risks": [
    {
      "risk": "主要风险",
      "mitigation": "应对建议"
    }
  ],
  "nextQuestions": ["后续需要进一步确认的问题"]
}
```

AI 输出要求：

- 用中文回答。
- 语气专业、务实、适合高校就业指导场景。
- 不制造确定性承诺，不承诺录取、入职或收入结果。
- 所有建议要能落到行动，不只给泛泛鼓励。
- 对升学、就业、转专业、求职等不同目标给出差异化路径。

## 官网页面规格

首页应包含：

- 首屏：产品名称、面向高校就业办的定位、一句价值说明、进入演示按钮。
- 场景说明：升学规划、就业准备、转专业咨询、简历与面试准备。
- 演示流程：填写学生画像、选择目标方向、生成规划建议、导出或复制结果。
- 输出样例：展示规划摘要、路径建议、行动清单、风险提醒四类结果。
- 适用对象：就业指导中心、学院辅导员、职业发展课程、招生就业处。
- 页脚：项目说明、DeepSeek API 配置提示、免责声明。

官网不需要登录入口、价格页、博客、案例库或后台入口。

## 演示工作台规格

演示页应包含：

- 学生画像表单：年级、专业、学校类型、技能基础、兴趣方向。
- 目标选择：升学、就业、转专业、实习、求职准备。
- 约束输入：地区、时间、预算、短板、偏好。
- 模式选择：标准规划、深度规划。
- 生成按钮：调用 `/api/plan`。
- 结果区：规划摘要、推荐路径、阶段行动、风险提醒、追问建议。
- 状态处理：加载中、成功、失败、API key 缺失、网络异常。

表单可以使用预设示例，方便访客一键体验。结果可以复制，但 V1 不需要下载 PDF、保存历史或分享链接。

## 验收标准

编码代理完成未来实现时，应满足：

- 项目可以通过环境变量连接 DeepSeek。
- 官网和演示工作台都能在浏览器中访问。
- 前端不会暴露 `DEEPSEEK_API_KEY`。
- `/api/plan` 能返回结构化规划结果。
- API key 缺失时有清晰错误提示。
- 页面内容全部围绕高校就业办和 AI 升学就业规划，不偏离成泛用聊天机器人。
- 没有登录、数据库、后台管理、文件上传或历史记录功能。

## 后续可扩展方向

这些能力不属于 V1，只作为未来方向：

- 学生档案和历史规划记录。
- 简历上传与简历诊断。
- 高校就业办管理后台。
- 批量生成班级或学院就业辅导建议。
- 接入学校真实就业数据、专业课程数据和岗位数据。
- 导出 PDF、生成辅导记录或课程作业反馈。
